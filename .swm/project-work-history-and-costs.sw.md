# Project Work History And Evaluation Costs

The project maintains two reviewable operational ledgers. `WORK_HISTORY.md` is
generated from `docs/work_history_sessions.json`,
`docs/work_history_days.json`, and `docs/work_history_milestones.json`. Those
inputs are refreshed from the local Chronicle session store and use a fixed
five-minute cap between consecutive turns. The result is an activity proxy,
not a payroll-grade timesheet.

Run the time refresh with:

```powershell
.\venv\Scripts\python.exe scripts\generate_work_history.py
```

`docs/EVALUATION_COSTS.md` is generated by
`scripts/aggregate_recorded_costs.py`. It selects one report-level recorded
cost per non-dry-run JSON artifact under `data/eval/`, excludes per-request
children and comparison aggregates, and drops a checkpoint when its finalized
counterpart exists. The result is a lower bound on estimated spend recorded by
project scripts, not a provider invoice. Runtime embedding calls and overnight
runs without cost artifacts remain unmeasured.

Run the cost refresh with:

```powershell
.\venv\Scripts\python.exe scripts/aggregate_recorded_costs.py
```

The ledgers are documentation artifacts: they should be reviewed alongside
`DOCS_INDEX.md`, and generated documentation should be checked with
`scripts/check_generated_docs.py` before committing.
