# One-pass issue map kit (for testing other models against Haiku)

Public law only (A2AJ dataset a2aj/canadian-case-law, Hugging Face, parquet per court; licence non-commercial). No database, no user text.

1. **Prompt:** `PROMPT_haiku_worker.md` is the exact brief each Haiku worker got (it reads `dec_N.json` and writes one JSON per decision). Output shape: `{"case_id","task":"issues","model","result":{"order_para":int,"overall_result":enum,"issues":[{"issue","paras","applicant_position","respondent_position","result","result_para","result_quote"}]}}`. Result enums: allowed_for_applicant, dismissed_for_applicant, partly_allowed, not_decided, moot_or_procedural. `result_quote` must be a verbatim substring (30 words max) of paragraph `result_para`; code checks that. Haiku outputs are in `haiku_outputs/`.
2. **Input:** `inputs/dec_N.json` = `{case_id, case, court, paragraphs:[{paragraph_index, text}]}`. Source: the A2AJ column `unofficial_text_en` for FC decisions; paragraphs split with regex `(?m)^\[(\d{1,3})\]\s+(.+?)(?=\n\[\d{1,3}\]\s|\Z)`. NOTE: `paragraph_index` is the running index of parsed paragraphs and sometimes differs from the judgment's own bracketed number (it skips when the source has gaps). Models must cite `paragraph_index`.
3. **Comparison set:** batch I = the 30 Federal Court decisions in `comparison_set_batch_I.json` (all 30 in `inputs/`). Fully graded.
4. **Grading:** `grading/GRADER_PROMPT.md` (blind grader: Sonnet reads last three paragraphs and the text of the paragraph each issue cites, no lawyer review). `grading/grader_input_g1.json` / `g2.json` are what the grader saw (shuffled, two halves of 15; builder shows `cited_para_text` cut at 1500 chars). `grading/batch_I_blind_grades.json` has per-issue `result_ok`, `para_ok`, `real_issue`, `harm`, and per-decision `overall_ok`.

Haiku result on batch I: 80 of 85 issue results right, 3 unclear, 2 wrong (one decision, 2009 FC 645, both harmful); 84 of 85 cited paragraphs right; overall right 29 of 30. To grade another model the same way, rebuild the grader input from its outputs with the same fields and use the same grader prompt in one pass with the Haiku outputs (grader strictness drifts between sessions).
