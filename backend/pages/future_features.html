Roadmap · a future-state goal for iLit

Future features and the work still to do

This page describes where iLit could go next and what stands in the way. It starts with the agency’s own documents, because that is where the largest value is: internal memos, briefs, repositories and private decisions, searched and analysed on the agency’s own hardware. Each item says what exists today, what is left to build and what it depends on. The pictures are concept mock-ups with invented sample data, not screenshots of working features.

The assumption behind it. The AI features assume the agency can run its own AI model on its own computers. The site’s normal search does not use AI at all, and nothing a person types is sent to an outside AI service. Where AI helps, it would run on that on-premises model or when decisions are added to the library, and its work would be stored as data that links back to the source paragraph.

Internal documentation: the agency’s own materials

The part of the roadmap that matters most to the agency. The public library is the starting point. The larger value is searching and analysing the agency’s own documents next to it, on the agency’s own hardware, with nothing leaving the building.

4

Data safety: nothing leaves the building

Concept only

The condition for everything above. It is a set of rules the system would be built on, not one feature.

Concept mock-up, not built yet · invented sample data

The data-safety rules this would be built on

  • Internal documents are stored only on the agency’s own servers.
  • The AI model runs on those servers. No outside AI service sees a question, memo or result.
  • Access follows the agency’s own sign-in and file permissions, and every search is logged for audit.
  • Uploaded files for a one-off check are read in memory and not kept.
  • Every AI-written label or summary is stored as data that links back to its source paragraph, so it can be checked.

What exists today

The public site already makes no AI calls when someone searches, and uploads are read in memory and discarded. The De-identify tool hands its key to the user and never keeps it. There is no sign-in, audit log or access control yet.

Still to do

  • Sign-in tied to agency accounts, with roles
  • An audit log of searches and document views
  • A deployment guide for an air-gapped or on-premises install

Depends on

  • Agency IT and security requirements
  • A decision on the hosting plan

Case fingerprints and similar cases

Partly built

A fingerprint describes a decision by its legal tags, statute sections and cited authorities, so the site can list similar decisions and say why.

Concept mock-up, not built yet · invented sample data

Similar cases · by subject and shared authorities

Sample v. Canada (MCI), 2022 FC 300Same subjectShares 6 authorities
Test v. Canada (MCI), 2020 FC 88Same subjectShares 2 authorities

Each match says why: the legal tags, statute sections and authorities the two decisions have in common.

What exists today

The method is built with no AI and tested on 4,599 decisions. It finds a different kind of neighbour from citation overlap alone, which remained the strongest signal for who is related to whom. The reader has a Similar cases panel that reads stored fingerprints and shows nothing for a decision that has none. I cannot confirm how much of the live library has them.

Still to do

  • Compute fingerprints for the whole library
  • Explain each match in plain words
  • Use them to seed alerts and the Workbench

Depends on

  • Computer time to compute them once
  • Spot checks by a lawyer

Smaller gaps on the list

Trust and accuracy

Outcome coding is being re-checked against a reviewed set. Some outcomes, such as the Supreme Court’s Vavilov, are known to be wrong on the live site until that finishes.

Save, export and hand off

Saved issues exported as a case list (CSV or Word), and a one-page issue brief that shows the number of decisions behind each figure.

Reader improvements

Paragraph citation shading, short extractive case summaries that point to the holding paragraph, and a fuller markup mode.

Hosting and backup

The database and site run on one personal computer and there is no backup yet. The long-term plan is a hosted Canadian cloud, and a backup should come first.
